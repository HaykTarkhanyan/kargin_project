# A static `import data from "./x.json"` into ANY `"use client"` tree bundles the whole file into a client JS chunk — it is not "loading a...

*From LEARNINGS.md, section "From the codebase-review cleanup (2026-06-22)".*

**A static `import data from "./x.json"` into ANY `"use client"` tree bundles the whole file into a client JS chunk — it is not "loading a data file."** Under Next static export, `web/lib/data.ts` did `import sketches from "@/public/data/sketches.json"` and exported `ALL`; four client pages imported `ALL`, so the entire 2.8 MB archive (every sketch's dialogue) got inlined into a 2.79 MB client chunk that the browser parses on the main thread before interactivity. The 702 `/sketch/[id]` pages did NOT pay this (they're server components prerendered to HTML — the JSON stays build-time). Two levers: (1) **ship less** — drop fields no client renders (here `lines`, a 1.15 MB array fully derivable from `text`, and an all-empty `segments`) → 2.79→1.60 MB; (2) for the rest, prefer a **server component** so the data never enters a client bundle (the soundboard page computed 12 tiles client-side over all 702 rows just to render static `<Link>`s — moved to build time). A faster algorithm doesn't help here; shipping less does.
